endpoints, generates arguments, and finds crashes, exceptions, and failed checks.

## How it works

A harness is a set of **endpoints**: small typed stubs that each call your API.

```cpp
STITCH_OBJECT(Store, kv_store*);
STITCH_OBJECT(Snapshot, kv_store*);

New<Store> load(Str<256> text) {
    kv_store* st = kv_load(text.c_str());
    stitch::require(st, "invalid text");
    return st;
}
STITCH_ENDPOINT(load);

void put(Borrow<Store> st, Str<16> key, Str<32> value) {
    stitch::require(kv_put(st, key.c_str(), value.c_str()) == 0, "invalid key or value");
}
STITCH_ENDPOINT(put);

void remove_key(Borrow<Store> st, Str<16> key) { kv_remove(st, key.c_str()); }
STITCH_ENDPOINT(remove_key);

New<Snapshot> snapshot(Borrow<Store> st) {
    char* text = kv_dump(st);
    kv_store* copy = kv_load(text);
    free(text);
    stitch::require(copy, "dump did not load");
    return copy;
}
STITCH_ENDPOINT(snapshot);
```

- **Objects** (`Store`, `Snapshot`) pass from one call to the next. `New<T>` makes one, `Borrow<T>`
  uses it, `Take<T>` consumes it.
- **Fuzzed parameters** (`Str<16>`, integers, bytes) are generated by the fuzzer.
- `require` rejects an input. `check` asserts a property; a failed check is reported as a bug.

The fuzzer **stitches** endpoints into programs, keeps the ones that reach new code, and mutates
both the arguments and the calls. A crash it found, minimized:

```
st = load("")
put(st, "tmp", "")
remove_key(st, "tmp")
snapshot(st)   // AddressSanitizer: heap-use-after-free in kv_dump
```

## Install

```sh
pip install stitch-fuzz
stitch setup --lang python
```

Requires Docker. The library, the harness and the fuzzer run in containers.

A project pins the STITCH++ release it is written for in its `stitch.toml`
(`stitch_version = "0.2.0"`); install that version to work on it. What changed between releases,
and what a harness has to change to upgrade: [CHANGELOG.md](CHANGELOG.md).

<details>
<summary>How each language is instrumented</summary>

| Language | Coverage | Comparisons (cmplog) | Bugs detected |
|---|---|---|---|
| C/C++ | SanitizerCoverage (clang) | `trace-cmp`, `memcmp`/`strcmp` hooks | ASan, UBSan, uncaught exceptions |
| Python | `sys.monitoring` line and branch events | AST rewrite of `==`, `!=`, `in`, `<` | undeclared exceptions |
| JavaScript | Babel plugin (CommonJS hook and ESM loader) | Babel rewrite of `===` and `switch`; `String`/`Set`/`Map` hooks | undeclared exceptions, prototype pollution, unhandled rejections |
| Java | Java agent, counters per basic block | `if_icmp`, `lcmp`, `switch`, `String.equals`/`startsWith`, `Map.get` | undeclared `Throwable`s |
| Go | `-d=libfuzzer` 8-bit counters | `libfuzzerTraceCmp*`, `libfuzzerHookStrCmp` | panics, fatal errors, data races (`-race`, optional) |
| Rust | SanitizerCoverage | `trace-compares`, ASan `memcmp` hooks | panics (including overflow checks), ASan |
| Ruby | Prism source rewriting | rewritten `==`, `<`, `eql?`, `start_with?`, `include?`, `case`/`when` | undeclared exceptions |
| Swift | SanitizerCoverage | `trace-cmp` | traps (bounds, overflow, nil unwrap), ASan |
| Objective-C | SanitizerCoverage (clang, GNUstep) | `trace-cmp`, `memcmp`/`strcmp` hooks, `NSString` comparison wrappers | Objective-C exceptions, ASan, UBSan |

In every language, failed `check`s in your stubs and timeouts are reported too. Details:
[`languages/README.md`](languages/README.md).

</details>
