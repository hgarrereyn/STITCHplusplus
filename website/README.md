# Docs site

The STITCH++ documentation, built with [Starlight](https://starlight.astro.build/).

```sh
npm install
npm run dev      # http://localhost:4321/
npm run build    # static site in dist/
```

- `src/content/docs/guide/`: the guide for humans, with the key-value store tutorial.
- The guide for agents is `skill/stitch/reference/*.md`, the same files the `stitch` skill and
  `stitch guide` use; `overview.md` is the entry point. The site serves each file raw at
  `/agents/<name>.raw.md` (`src/pages/agents/`, `src/agent-guide.ts`) and rendered at
  `/agents/<name>.md/`, with a link to the raw file under the title.
- `src/content/docs/agents/` and `src/content/docs/reference/` are generated by
  `scripts/sync-reference.mjs` from `skill/stitch/reference/*.md`. Edit those files instead.

The tutorial's code is shown per language with `<Lang id="...">` blocks
(`src/components/Lang.astro`). Pages with `languages: true` in their frontmatter show the language
picker under the title. The finished tutorial harnesses are in `examples/<lang>-demo/`.

Command output in the tutorial comes from running it in each language, and is stored in
`src/tutorial-output/<lang>/<name>.txt`. `<RunOutput name="...">` shows the picked language's file.
When the CLI's output changes, run the tutorial again and replace those files.

The home page example is in `src/showcase/<lang>/`: `harness.txt`, a spec for the key-value store
with two object types, and `trace.txt`, a crash a 90-second run of it found. `showcase.ts` describes
its endpoints (their shapes and notes) and where each part is in each language's file; the build
fails if an anchor is missing. `glyph.ts` and `program.ts` draw endpoints and programs.

`.github/workflows/docs.yml` publishes the site to GitHub Pages on pushes to `main`.
