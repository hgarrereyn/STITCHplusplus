## Write the crash as a file

```sh
stitch write c5
```

```
wrote .stitch/standalone/c5/repro.py (73 lines, 4 calls, crash in call #3)
  expected: KeyError in Store.items
SAME CRASH: .stitch/standalone/c5/repro.py -> KeyError in Store.items
```

The file holds your stubs and a `main` that calls them with the recorded arguments:

```python
def main():
    # #0 load(text)
    store0 = stitch.call(0, 'load', lambda: load(''))
    # #1 put(st=store0, key, value)
    stitch.call(1, 'put', lambda: put(store0, 'tmp', ''))
    # #2 remove(st=store0, key)
    stitch.call(2, 'remove', lambda: remove(store0, 'tmp'))
    # #3 roundtrip(st=store0)  <-- crashes here in the original run
    stitch.call(3, 'roundtrip', lambda: roundtrip(store0))
```

## Shrink it

Copy the file and cut it down to plain library calls. After each edit, run `stitch try`: it builds
and runs the file and compares the crash with the original.

```sh
cp .stitch/standalone/c5/repro.py .stitch/standalone/c5/min.py
# edit min.py
stitch try .stitch/standalone/c5/min.py
```

## A reproducer with its environment

`stitch repro` writes a folder that rebuilds the library and replays the crash with nothing but
Docker, and checks that it works:

```sh
stitch repro c5
```

```
[stitch] verified: same crash
reproducer: .stitch/repros/kv-c5
  run it anywhere with docker: .stitch/repros/kv-c5/run.sh
```

## Is it fixed upstream?

When the project's source is a git repository (`stitch init --git URL --rev REV`), you can run a
crash against other versions:

```sh
stitch exec c5 --rev HEAD      # does the newest code still crash?
stitch bisect c5               # the commit that introduced the bug
stitch bisect c5 --fixed       # the commit that fixed it
```

## What you have done

- described an API with stubs, objects and fuzzed parameters
- used the probe report to find a stub that wasted runs, and fixed it with a data type
- asserted a property with a check
- grouped crashes, separated three bugs, and reduced one to four lines

The finished harness is in `examples/<language>-demo/harness/`. It has a few more stubs than this
tutorial, including `put_all`, which takes a list of pairs from a decoder. [Concepts](/STITCHplusplus/guide/concepts/)
covers the ideas in more depth, and [Reference › Languages](/STITCHplusplus/reference/languages/python/) has the full
API for each language.
