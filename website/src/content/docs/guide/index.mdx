STITCH++ finds bugs in libraries by calling their API with generated inputs. It supports C/C++,
Python, JavaScript, Java, Go, Rust, Ruby, Swift and Objective-C, and works the same way in each.

## How it works

You write **stubs**: small typed functions that each make one API call.

<Lang id="python">
```python
@stitch.endpoint(bails_on=(ValueError,))
def load(text: Str[256]) -> New[Store]:
    return kvlib.load(text)

@stitch.endpoint
def remove(st: Borrow[Store], key: Str[16]):
    st.remove(key)
```
</Lang>
<Lang id="cpp">
```cpp
New<Store> load(Str<256> text) {
    kv_store* st = kv_load(text.c_str());
    stitch::require(st, "invalid text");
    return st;
}
STITCH_ENDPOINT(load);

void remove_key(Borrow<Store> st, Str<16> key) { kv_remove(st, key.c_str()); }
STITCH_ENDPOINT(remove_key);
```
</Lang>
<Lang id="javascript">
```js
stitch.endpoint("load", { text: Str(256) }, New(Store), ({ text }) => kv.load(text),
  { bailsOn: [RangeError] });

stitch.endpoint("remove", { st: Borrow(Store), key: Str(16) }, null, ({ st, key }) => st.remove(key));
```
</Lang>
<Lang id="java">
```java

    return Store.load(text);
}

@Endpoint
public static void remove(Store st, @Str(max = 16) String key) {
    st.remove(key);

```
</Lang>
<Lang id="go">

```swift

    New(try KVSwift.load(text.value))
```

<Lang id="objc">
```objc
STITCH_ENDPOINT(New(Store), load, Str(256) text) {
    KVStore *st = [KVStore storeWithText:text error:NULL];
    STRequire(st != nil, @"invalid text");
    return st;
}

STITCH_ENDPOINT(void, remove, Borrow(Store) st, Str(16) key) {
    [st removeKey:key];
}
```
</Lang>

The fuzzer **stitches** stubs into programs: it creates a store with `load`, removes a key from that
store, and so on. It generates the arguments, keeps the programs that reach new code, and
mutates them: changing arguments, and inserting, deleting and rewiring calls.

It reports:

- crashes and sanitizer reports (ASan, UBSan)
- panics, traps and exceptions your stubs did not declare
- failed `check`s: properties you assert, such as "dump then load gives the same store"
- programs that run past a timeout

For each bug, STITCH++ shows the calls that led to it, minimizes the program, and writes it as a
standalone reproducer.

## What you need

- Docker with buildx
- Python 3.9 or newer, for the `stitch` command

The library, the harness and the fuzzer all build and run in Docker. You don't need the
language's toolchain on your machine.
