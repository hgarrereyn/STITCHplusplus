The tutorial uses most of these ideas. This page explains each one on its own. The syntax summary
for the language you picked is at the [end of the page](#syntax).

## Stubs and programs

A stub makes one API call. Its signature declares what it needs (objects and fuzzed parameters)
and what it produces (new objects). A program is a list of stub calls, where each object input
refers to an output of an earlier call. `stitch exec --trace` prints programs like this:

```
[stitch] #0 new_store()
[stitch]     -> ok produced o0.0
[stitch] #1 put(st=o0.0, key=Str[4]"tmpa", value=Str[1]"x")
[stitch]     -> ok
[stitch] #2 remove(st=o0.0, key=Str[4]"tmpa")
[stitch]     -> ok
```

`o0.0` is output 0 of call 0.

## Objects

An object is a value that one call produces and later calls use: a store, a parsed document, a
file handle. Each object has a type that you name in the harness.

- **Borrow**: the call uses the object. It stays available for later calls.
- **Take**: the call consumes the object. Later calls can't use it.
- **New**: the call returns a new object.

When the library takes ownership of an input only if the call succeeds, borrow it and mark it
consumed after the call succeeds.

A stub can have several outputs, and an output can be optional. A parser that returns either a
table or an array can return both as optional outputs, so that stubs that need a table get one.

Write one producer per kind of object (`new_number`, `new_string`), not one producer with a
`kind` parameter. The fuzzer learns which producer each consumer needs.

## Fuzzed parameters

Every parameter that is not an object is fuzzed:

| Kind | Value |
|---|---|
| integers, floats, booleans | any value of the type |
| range | an integer between two bounds |
| one of | one value from a list of constants |
| flags | the OR of a subset of flags |
| string, bytes | at most a given number of bytes, optionally tagged with a data type |
| file | the path of a temporary file holding the data |
| value | whatever a data type's decoder returns: a list, a struct, a record |
| source | a stream of choices to use inside the stub |

Prefer a range or a list of values to a plain integer that the stub then rejects. A stub that
rejects most values wastes runs.

A source picks among things that exist at run time, such as an existing key:

```python
@stitch.endpoint
def remove_existing(st: Borrow[Store], s: Src[8]):
    keys = sorted(k for k, _ in st.items())
    stitch.require(keys, "empty store")
    st.remove(s.pick(keys))
```

Sort before picking, so that a program replays the same way.

## Bails, bugs and checks

A **bail** is an expected failure: invalid input or an unmet precondition. The call produces
nothing, the calls that need its outputs are skipped, and the rest of the program runs.

A **bug** is anything else: a crash, a sanitizer report, a panic or trap, an exception the stub
did not declare, a failed check, or a program slower than `timeout_ms`.

A **check** is a property you assert: `check(cond, "what")`. Good checks hold for every input:

- round trips: `load(dump(x))` equals `x`
- idempotence: `normalize(normalize(x)) == normalize(x)`
- agreement: two APIs that compute the same thing give the same result

## Data types

A data type is a tag on a string or bytes parameter, such as `Str[256, KvText]`. Its folder
`harness/data/KvText/` can hold:

- `seeds/`: sample inputs, one per file
- `*.dict`: tokens, one quoted string per line
- a **decoder** in the harness, which builds a value from fuzzer choices

A decoder draws from a source: `s.str(8)` for text, `s.token()` for a dictionary token,
`s.range(0, 9)` for a number, and `while s.more():` to loop. Mutations change the choices, so
decoded values stay well formed. `stitch sample KvText -n 5` prints values a decoder makes.

A decoder can return any value, not only text. A parameter of type `Val` receives it. Decoders can
call each other with `s.draw(Other)`.

## Attributes

An attribute is a value the harness stores on an object, for facts the library can't tell you:

```python
stitch.set(st, "frozen", True)          # in a freeze stub
stitch.require(not stitch.get(st, "frozen", False), "frozen")   # in stubs that modify
```

Ask the library first; use an attribute only when there is no API for the fact. A stub that copies
an object should copy its attributes too.

## Campaigns and the corpus

`stitch fuzz` starts a **campaign** (named `main` unless you pass `--name`). It keeps a
**corpus**: the programs that reached new code. Running `stitch fuzz` again resumes the corpus.
`stitch probe` is a short campaign named `probe`, used to check the harness. Crash ids (`c1`,
`c2`, ...) are numbered per campaign.

## Syntax

<Lang id="python">
| Concept | Python |
|---|---|
| stub | `@stitch.endpoint` on a function; `@stitch.endpoint(bails_on=(ValueError,))` |
| object type | `Store = stitch.object("Store")` |
| borrow, take, new | `st: Borrow[Store]`, `st: Take[Store]`, `-> New[Store]` |
| optional output | `-> New[Store] \| None`; several: `-> tuple[New[A], New[B] \| None]` |
| integers, floats | `I64`, `U8`, `F64`, `bool`, ... |
| range, one of, flags | `Range[0, 9]`, `OneOf["a", "b"]`, `Flags[1, 2, 4]` |
| string, bytes, file | `Str[64]`, `Bytes[256, Tag]`, `File[4096, Tag]` |
| value, source | `Val[Tag, 256]`, `Src[8]` |
| bail, require, check | `stitch.bail(r)`, `stitch.require(c, r)`, `stitch.check(c, what)` |
| data type, decoder | `Tag = stitch.datatype("Tag")`, `@stitch.decoder(Tag)` |
| attributes | `stitch.set(x, k, v)`, `stitch.get(x, k, default)` |
